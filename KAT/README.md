# Known-answer test sets

This directory keeps two KAT generations separate because the fixed-precision
Compact-SQIsign key-generation path is intentionally not bit-for-bit identical
to the original GMP implementation.

## `legacy-nist-v2`

These are the original 100-vector SQIsign NIST-v2 files.  They are preserved
byte-for-byte from the
[`nist-v2` source commit](https://github.com/SQISign/the-sqisign/tree/91e9e464fe5400192d13e1f9240cbf180200a103)
(`91e9e464fe5400192d13e1f9240cbf180200a103`) and are used in `verify-only`
mode.  They check that this implementation still accepts the published public
keys and signatures; they are not replay vectors for Compact-SQIsign key
generation.

| lvl5 | `2509ecc191791385968a36db50d8479c87d3e1b8bd655150f927f1f5613f2546` |

## `compact-v1`

These files were generated by the fixed-precision code in this repository.
They contain vector 0 for each security level and are tested in two ways:

- `verify-only` checks each stored Compact-SQIsign signature.
- `replay` resets the NIST CTR-DRBG from vector 0's stored seed, regenerates the
  key pair and signature, compares `pk`, `sk`, and `sm` byte-for-byte, and
  verifies the result.

| level | request SHA-256 | response SHA-256 |
| --- | --- | --- |
| lvl1 | `cce2e6a0e6aff1179eba6b8b5cb1b096e751f9aafdf8934a2df857164a902202` | `f65e08e2b0a3cb1f77ec2238b99996f8221443da6082d42cbcf26e106d8e3004` |
| lvl3 | `cce2e6a0e6aff1179eba6b8b5cb1b096e751f9aafdf8934a2df857164a902202` | `46a98461d5a8160eb3d36309d8df61c68a2309ab50ebcc3a461e3ccc1ee53497` |
| lvl5 | `cce2e6a0e6aff1179eba6b8b5cb1b096e751f9aafdf8934a2df857164a902202` | `28caf3ad4f4d2a4756c240e772dfeffcf2c7e46c499fbaa344ea1e73e3c540c0` |

The committed Compact set is deliberately one vector per level: level-5
signing is too slow for a 100-vector replay in routine CI.  The complete legacy
set remains covered by verification, while randomized KeyGen/Sign/Verify
self-tests provide additional correctness coverage.  KAT reproducibility is a
regression check, not by itself a proof of scheme correctness.

## Regeneration

Configure a Release signing build, build all three generators, and run:

```sh
KAT_VECTORS=1 scripts/gen_kat_files.sh build KAT/compact-v1
```

`PQCgenKAT_sign_<level>` accepts `--vectors N` for `1 <= N <= 100` and
`--output-dir DIR`.  Set `KAT_VECTORS=100` only for a full release-generation
run.  The script generates every requested level in a temporary directory and
installs files only after all generators succeed.
