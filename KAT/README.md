# Known-answer test sets

This directory keeps two KAT generations separate because the fixed-precision
Compact-SQIsign key-generation path is intentionally not bit-for-bit identical
to the original GMP implementation.

## `legacy-nist-v2`

These are the original 100-vector SQIsign NIST-v2 files.  They are preserved
byte-for-byte from the
[`nist-v2` source commit](https://github.com/SQISign/the-sqisign/tree/91e9e464fe5400192d13e1f9240cbf180200a103)
(`91e9e464fe5400192d13e1f9240cbf180200a103`).  They are archived for provenance
and are intentionally not registered as CTest tests: Compact key generation
uses a different random transcript, and these files are not an oracle for the
Compact implementation.

## `compact-v1`

These files were generated by an earlier fixed-precision revision of this
repository. They contain vector 0 for each security level and are retained as
signature-verification regression fixtures:

- `verify-only` checks each stored Compact-SQIsign signature.

Byte-for-byte `replay` is intentionally not registered. Compact ML2 and the
order-relative `O*x + N*O` construction consume a different deterministic key
transcript, so the archived public key is not a correctness oracle for the
current implementation.

The stored-vector verification tests are disabled by default. Configure with
`-DENABLE_KAT_TESTS=ON` and run `ctest -L regression` to enable the Compact
fixtures. The committed set is deliberately one vector per level.

KAT reproducibility is a regression check, not by itself a proof of scheme
correctness.  The default suite instead exercises fixed-seed
KeyGen/Sign/Verify/Open properties, malformed-length and tamper rejection, and
checks the Compact ML2 lattice span against an independent exact-HNF oracle.

## Regeneration

Configure a Release signing build, build all three generators, and run:

```sh
KAT_VECTORS=1 scripts/gen_kat_files.sh build KAT/compact-v1
```

`PQCgenKAT_sign_<level>` accepts `--vectors N` for `1 <= N <= 100` and
`--output-dir DIR`.  Set `KAT_VECTORS=100` only for a full release-generation
run.  The script generates every requested level in a temporary directory and
installs files only after all generators succeed.
